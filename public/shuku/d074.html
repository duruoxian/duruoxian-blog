408 · 计算机网络精讲 · 网络层（原理推导 + 计算详解）

网络层是408的"计算第二大户"：子网划分、CIDR聚合、IP分片、最长前缀匹配年年必出。本册把每类计算做成可复现的模板，原理讲透"为什么这样设计"。 配套：《计算机网络_知识点与难点》《考题集》《易错点与陷阱清单》；Dijkstra算法过程演算见《408_综合题精讲》题4。

一、IPv4 协议精讲

P1 首部逐字段（20B固定+0~40B可选）： | 字段 | 位数 | 要点 | |---|---|---| | 版本 | 4 | 4=IPv4 | | 首部长度 | 4 | 单位4B，故首部20~60B（1111=60B） | | 区分服务 | 8 | | | 总长度 | 16 | 单位1B，首部+数据 ≤65535B | | 标识 | 16 | 同一数据报的分片相同（重组用） | | 标志 | 3 | DF（=1禁止分片，需分片则丢弃+回ICMP差错）、MF（=1后面还有分片） | | 片偏移 | 13 | 单位8B（相对原数据起点的偏移/8） | | TTL | 8 | 每过一路由器−1，=0丢弃并回ICMP超时（防环） | | 协议 | 8 | 6=TCP，17=UDP，89=OSPF，1=ICMP | | 首部校验和 | 16 | 只校验首部，每跳重算（TTL在变） | | 源/目的IP | 各32 | |

P2 分片（计算模板）： ① 每片可载数据 = MTU − 20（首部），再向下取 8的倍数（除最后一片）； ② 片偏移 = 该片数据在原数据中的起始字节 ÷ 8；MF：最后一片为0； ③ 中间路由器只分片不重组，重组只在目的主机； ④ DF=1 且需要分片 → 丢弃并回ICMP"终点不可达（需要分片但DF置位）"。

考题1（分片全程演算） 一个总长度3820B的IP数据报（首部20B），经过MTU=1420B的链路。求各分片的总长度、数据长度、片偏移、MF。 【解】数据3800B；每片数据≤1420−20=1400B（恰为8的倍数）→ 1400+1400+1000=3800 ✓ | 分片 | 总长度 | 数据长度 | 片偏移(8B) | MF | |---|---|---|---|---| | 1 | 1420 | 1400 | 0 | 1 | | 2 | 1420 | 1400 | 175（1400/8） | 1 | | 3 | 1020 | 1000 | 350（2800/8） | 0 | 最后一个分片的偏移=350×8=2800，加上1000=3800 ✓ 拼接自洽。∎

P3 IPv4地址与子网： - 分类地址：A(0开头,/8)、B(10,/16)、C(110,/24)、D组播、E保留；特殊：全0=本机/网络，全1=广播，127/8环回。 - 私有地址（不出公网）：10/8、172.16/12、192.168/16。 - 子网掩码：/n → 主机位 32−n；块大小=2^{32−n}（网络地址按块对齐）；可用主机=2^{32−n}−2。 - CIDR：消除A/B/C类别，"IP前缀+掩码长度"；路由聚合=取各网络地址的公共前缀。

二、子网划分与聚合（计算模板四件套）

模板1 等分划分：/24分4个子网 → 借2位→/26，块大小64：.0/.64/.128/.192。 模板2 VLSM（不等长）：大需求先用大块，从地址空间低端依次向下切。 模板3 聚合：把各网络地址写成二进制，取公共前缀（掩码缩短到该长度）。 模板4 最长前缀匹配：目的地址与多条路由都匹配时选前缀最长的（最具体的路由）；都不匹配走默认路由0.0.0.0/0。

考题2（VLSM划分·真题级） 单位分得 192.77.33.0/24，需求：子网A 100台主机、B 50台、C 25台、D 25台。给出划分方案。 【解】主机数要求：100→/25（126）；50→/26（62）；25→/27（30）。 | 子网 | 前缀 | 范围 | 可用 | |---|---|---|---| | A | 192.77.33.0/25 | .0~.127 | 126 | | B | 192.77.33.128/26 | .128~.191 | 62 | | C | 192.77.33.192/27 | .192~.223 | 30 | | D | 192.77.33.224/27 | .224~.255 | 30 | 地址利用率=(126+62+30+30)/256≈97%——VLSM按需切分避免等分浪费。∎

考题3（CIDR聚合） 路由器R1的直连网段 202.118.1.0/24 与 202.118.2.0/24，向R2通告时可聚合为？ 【解】第三字节：1=00000001，2=00000010 → 公共前缀 000000（6位）。 聚合=202.118.000000 00/22 即 202.118.0.0/22（覆盖 .0.0~.3.255，含两条路由）。∎ （验证：.1.0 与 .2.0 的第22位起都是各自空间。聚合代价=路由表变小但可能引入"多覆盖"的无效地址。）

考题4（最长前缀匹配） 路由表：①192.168.20.0/24 → 接口E0；②192.168.0.0/16 → 接口E1；③0.0.0.0/0 → 接口E2（默认）。目的地址192.168.20.7 与 192.168.21.7 各走哪个接口？ 【解】192.168.20.7：与①(/24)、②(/16)都匹配 → 最长前缀 ①E0。 192.168.21.7：只匹配② → E1。 （若目的为8.8.8.8 → 只匹配③默认路由。）

三、路由协议精讲

R1 三协议对比（必背表）： | | RIP | OSPF | BGP | |---|---|---|---| | 类型 | 内部IGP | 内部IGP | 外部EGP | | 算法 | 距离向量 | 链路状态 | 路径向量 | | 度量 | 跳数（≤15，16=不可达） | 代价(带宽) | 策略/路径属性 | | 交换对象 | 相邻路由器，整张表 | 全网洪泛链路状态通告 | 相邻AS，完整路径 | | 封装 | UDP 520 | IP直封（协议号89） | TCP 179 | | 收敛 | 慢（坏消息传得慢） | 快 | 慢（策略优先） | | 规模 | 小网络 | 分区域（Area 0主干） | 互联网级 | 【防环】RIP：最大跳数16、水平分割、毒性逆转、触发更新；OSPF天然无环（全图最短路径）。

R2 RIP更新演算（距离向量更新规则）：收到邻居通告的距离+1（经过该邻居），与自身表比较取小，取小则更新下一跳为该邻居。

考题5（RIP表更新） R1当前到网络N的距离为11（下一跳R3）。收到R2发来的距离向量中"到N距离5"。更新后？ 【解】经R2的距离=5+1=6 < 11 → 更新为6，下一跳R2。 若R2通告的是16（不可达）且原下一跳恰是R2 → 置16（不可达）。∎ （慢收敛："到N不可达"的消息与"我还经你到N"的旧消息互相抬价，跳数滚到16才停——需水平分割/毒性逆转治理。）

R3 OSPF要点：向全网洪泛链路状态通告LSA → 每台路由器得到全网的链路状态数据库 → 各自跑Dijkstra算最短路径树；划分区域减少洪泛与路由表规模（区域边界路由器ABR、主干区域Area 0）。

四、ICMP · ARP · DHCP · 组播

I1 ICMP：差错报告（终点不可达3、超时11、参数问题12、改变路由5）+ 询问（回送请求/回答→ping、时间戳）；ICMP封装在IP中（网络层协议却"帮"着反馈差错）。 【不发送ICMP差错报告的四种情况】对ICMP差错报文本身、对第一个分片之后的后续分片、对具有组播地址的数据报、对特殊地址（127.0.0.1、0.0.0.0）。 I2 ARP：同一局域网内 IP→MAC。过程：查缓存→无则广播ARP请求（目的MAC=FF-FF-FF-FF-FF-FF）→目标主机单播回ARP响应→写入缓存（有生存期）。 【要点】跨网段解析的是默认网关的MAC（不是远端主机）——因为帧只在链路层走一跳。 I3 DHCP（应用层协议，基于UDP 67/68）：DISCOVER（广播）→OFFER→REQUEST（广播）→ACK；可跨网段由DHCP中继代理转发（单播到服务器）；分配IP+掩码+网关+DNS+租期。 I4 IP组播：D类地址；IGMP让路由器知道本网段有哪些成员；组播路由协议在路由器间构建组播树。

五、IPv6

P1 要点：128位地址；首部固定40B；取消了首部校验和（减轻路由器负担）；只允许源节点分片（路由器不分片→路径MTU发现）；取消选项字段改扩展首部；即插即用（自动配置）。 P2 地址：冒号十六进制，零压缩（连续全零段→::，只许一次）；前缀划分（全球单播2000::/3、链路本地FE80::/10、组播FF00::/8）；::1回环。 P3 过渡：双协议栈、隧道（IPv6包封在IPv4里穿越）、（NAT-PT已淘汰）。

本章考题补遗（2题）

题6（TTL与traceroute原理） 主机执行 tracert 到远端服务器，简述其原理。 【解】依次发送 TTL=1,2,3,… 的分组：第 i 个分组在第 i 跳路由器 TTL 减到0 → 路由器丢弃并回送ICMP超时报文 → 源主机由此测得第 i 跳地址与往返时间；到达终点时（TTL足够）因目的端口不可达回送ICMP终点不可达 → 结束。∎

题7（ARP全过程） 主机A（192.168.1.10/26）首次与网关（192.168.1.1）通信，描述ARP过程；若目的改为远程服务器8.8.8.8，ARP解析的对象变吗？ 【解】A查缓存无网关MAC → 广播ARP请求"谁是192.168.1.1" → 网关单播应答自己的MAC → A缓存并把目的IP=8.8.8.8、目的MAC=网关MAC的帧发出。 改为8.8.8.8：解析对象不变，仍是网关的MAC（IP端到端不变、MAC逐跳更换——跨网段通信的核心规律）。∎
