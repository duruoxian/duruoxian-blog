408 · 计算机组成原理精讲 · 存储系统（Cache三映射计算 + 主存扩展演算）

计组精讲第2批。存储系统是计组计算题的绝对主战场：Cache地址划分、平均访存时间、芯片扩展、多体交叉——本册每类给推导模板与验算。

一、层次结构精讲

H1 三级存储层次：Cache–主存（解决速度匹配，由硬件自动完成，对程序员透明）+ 主存–辅存（解决容量，由硬件+OS共同完成，发展为虚拟存储）。 【理论根基】局部性原理——时间局部性+空间局部性：整个层次体系能成立的唯一原因（第7章OS题9、第5章数学题4呼应）。 H2 三层次参数金字塔：速度：寄存器>Cache(SRAM)>主存(DRAM)>辅存(Flash/磁盘)；位价相反；容量相反。 【要点】层次间"数据流向"：Cache↔主存以块为单位（几十字节），主存↔辅存以页为单位（几KB）——块小页大，因为速度差不同。

二、主存精讲

M1 SRAM vs DRAM（必背对比表）： | | SRAM | DRAM | |---|---|---| | 存储原理 | 触发器 | 电容存储电荷 | | 刷新 | 不需要 | 需要（电荷泄漏） | | 运行 | 快 | 慢 | | 集成度/位价 | 低/贵 | 高/便宜 | | 用途 | Cache | 主存 | M2 DRAM刷新：集中刷新（死时间）、分散刷新（无死时间但存取周期加倍）、异步刷新（2ms内分散刷完，每行间隔2ms/行数）——现代主流。 M3 ROM族：MROM→PROM→EPROM→EEPROM（按字节电擦除，BIOS）→Flash（按块擦除，SSD/U盘）。Flash读快写慢（写前擦除）、块擦写次数有限→磨损均衡。

M4 主存芯片扩展（三步模板）： ① 位扩展：位数不够→多片并联（地址、片选共用）； ② 字扩展：字数不够→高位地址经译码器产生片选； ③ 字位同时扩展：芯片数 = 总容量/(单片容量)。 【地址划分】片内地址=⌊log₂(每片字数)⌋位，片选=剩余高位（经译码器）。

考题1（芯片扩展） 用 4K×4位 的SRAM芯片组成 16K×8位 的存储器，需要多少片？地址线、片选如何安排？ 【解】芯片数=(16K×8)/(4K×4)=8片。 位扩展：每2片并联构成4K×8（一组）；字扩展：4组 → 2-4译码器对高2位地址译码产生4个片选。 地址14位：高2位=组选（译码），低12位=片内地址。∎

M5 多体交叉存储器： - 高位交叉（顺序编址）：高位选体——体间顺序扩展，无并行效果； - 低位交叉（各体轮流编址）：低位选体——流水线存取：连续访问m个字，时间=T+(m−1)×r（r=总线传送周期，T=存取周期，r=T/分体数）。 【推导】第 i 个字在体 i mod 4：访问体0的同时，体1已在传送——四体流水使带宽×4（理想）。

考题2（多体交叉计算） 四体低位交叉，存取周期1μs，总线传送周期0.25μs。连续读取16个字的总时间？高位交叉呢？ 【解】低位交叉：T+(m−1)r=1+15×0.25=4.75μs； 高位交叉（同一体内连续）：16×1=16μs。∎ （注意：4个字恰好跨4体需 1+3×0.25=1.75μs；"体数≥一次读取字数"才能满流水。）

三、Cache 精讲（重中之重）

C1 工作原理：主存块调入Cache，CPU访存先查Cache（并行比较标记）→命中直接取、缺失则调块+替换。 C2 命中率与平均访存时间（两版公式）： - Cache与主存同时访问（并行）：EAT = h·t_c + (1−h)·t_m； - 先Cache后主存（串行）：EAT = h·t_c + (1−h)(t_c+t_m)。 考题3（EAT双版计算） Cache存取40ns，主存200ns，命中率90%。求串行与并行两版的平均访存时间。 【解】并行：0.9×40+0.1×200=36+20=56ns； 串行：0.9×40+0.1×(40+200)=36+24=60ns。∎ （题干说"同时访问/先查Cache再查主存"决定用哪个公式——408审题陷阱。）

C3 三种映射（地址划分是全部计算的核心）： 设主存地址 n 位，块大小 2^b B（块内偏移 b 位），Cache 行数 2^c： | 映射 | 主存地址划分 | 特点 | |---|---|---| | 直接映射 | 标记 | 行号(c位) | 块内(b位) | 行号=块号 mod 行数；一行只容一块→冲突颠簸；硬件最简 | | 全相联 | 标记(n−b位) | 块内(b位) | 任意放→命中率高、比较电路庞大 | | 组相联（2路等） | 标记 | 组号(g位) | 块内(b位) | 组间直接、组内全相联；折中 |

考题4（三映射地址划分·必考演算） 主存地址16位，块大小16B，Cache 64行。①直接映射下主存地址 0x2C45 的标记、行号、块内偏移？②改为2路组相联呢？③直接映射下访问地址序列 0,16,32,0,16（十进制字节地址）的命中情况？ 【解】块内偏移=log₂16=4位。 ①直接映射：行数64=2⁶ → 行号6位；标记=16−6−4=6位。 0x2C45=0010 1100 0100 0101₂：偏移=0101=5；行号=000100=4；标记=001011=11。 ②2路组相联：组数=64/2=32=2⁵ → 组号5位；标记=16−4−5=7位。0x2C45：组号=00100=4，标记=0010110=0x16，偏移5。 ③直接映射4行、块16B：地址0、16、32的行号均为0（0÷16 mod 4），16→行0，32→行0： 0M（装0块）、16M（同块，命中！）？——0、16同属块0（16/16=1? 16号块=1，0号块=0！）修正：块号=地址/16：0→块0行0，16→块1行1，32→块2行2，0→块0命中，16→块1命中。命中2/5。 【颠簸演示】改序列 0,64,128,0,64（块0、4、8均映射行0）：0M、64M、128M、0M、64M → 命中0/5——直接映射的冲突颠簸（同行互相挤）。∎ （映射题万能流程：①偏移位数=块大小幂；②行号/组号位数=Cache规模幂；③剩余=标记；④把地址写成二进制切段。）

C4 替换算法：直接映射无需替换（位置固定）；全相联/组相联满时替换——LRU（计数器/栈，堆栈算法）、FIFO、LFU、随机。LRU硬件实现：每行计数器或栈表。 C5 写策略： - 写命中：全写法（同时写Cache与主存，配写缓冲）——实现简单但写主存频繁；回写法（只写Cache置脏位，换出时写回）——快但有一致性风险； - 写不命中：写分配（调入块，配回写法）/非写分配（直接写主存，配全写法）。 【配对】全写↔非写分配；回写↔写分配（主流组合）。 C6 多级Cache：L1/L2/L3——局部性+层次思想的再应用；缺失开销逐级增大。

四、虚拟存储（与Cache类比）

V1 页式虚拟存储：虚页号→查页表→实页框号（与Cache组相联思想同构：TLB=页表的Cache）。 V2 段式/段页式：段=程序逻辑单位（二维、便于共享保护）；段页式=先分段再分页（三次访存，快表救场）。 V3 与Cache的类比表（985面试）：块↔页、Cache行↔页框、标记↔虚页号、命中↔不在缺页、缺失处理：Cache由硬件、缺页由OS（内中断）——"硬件透明 vs 软件介入"是两级的本质区别。

本章考题补遗（2题）

题5（程序局部性·985面试） 遍历1000×1000的int数组（行优先存储，块大小可容多行片段），为什么 for i: for j: a[i][j] 比 for j: for i: a[j][i] 快得多？ 【答】行优先存储下，a[i][j] 内层 j 连续增长 → 空间局部性：一次调块（如64B=16个int）命中16次。反序后每步跳过4KB（一行），每次访问都换块 → 缺失率从1/16升到100%，Cache/TLB全废。∎ （结论：遍历顺序要与存储顺序一致——这就是"写代码照顾Cache"的原理。）

题6（Cache容量/位数综合） 32位地址、块64B、2路组相联、数据区512KB。求Cache总位数（含标记与有效位）。 【解】数据512KB → 行数=512KB/64B=8192=2¹³行 → 组数=2¹²组 → 组号12位；块内6位；标记=32−6−12=14位。 每行：数据 64×8=512bit + 标记14 + 有效1 + （脏位1，回写法）= 528bit。 总位数=8192×528≈4.32Mbit≈540KB（数据512KB+元数据开销约5.5%）。∎ （Cache总容量的"位"级计算——408真题标准考法：数据+标记+有效位+脏位逐项加。）
