AI方向 · LLM与Agent应用精讲（第4/5批）

你的方向声明：偏向 LLM 应用与 AI Agent（大模型、智能体、RAG、工具调用），而非传统ML理论。 定位：本册是"方向核心课"——读研做Agent方向、以及复试谈方向时用的主力知识；复试基础题仍以第2、3批（ML/DL）为主，本册负责"聊方向"环节的深度。知识截至2026年的主流共识，具体框架版本以入学时生态为准。

一、LLM 大模型基础（Agent的地基）

1.1 从Transformer到GPT：Decoder-only自回归

  • 回顾第3批：Transformer编码器-解码器；GPT系只用解码器：因果掩码（只看左边）+自回归（预测下一个token，再把预测拼回输入继续）；
  • 训练目标简单到离谱：next token prediction（海量文本上预测下一个词）——规模上来后"涌现"出推理、指令遵循、in-context learning；
  • Tokenization：文本切成token（BPE子词），上下文窗口=能处理的token数（ attention是O(n²)，窗口是核心资源）。

1.2 三阶段训练管线（必背）

预训练（next token，海量无标注）→ SFT监督微调（指令-回答对，学会"听指令"）→ RLHF/对齐（人类偏好排序训练奖励模型+强化学习，学会"说人话、无害"）。 后期简化版：DPO（直接偏好优化，绕开RL）——概念级了解。

1.3 推理与采样（复试爱问"温度是什么"）

  • 温度T：softmax前logit除以T。T→0贪心（确定、保守）；T大→分布平坦（多样、发散）。写代码/事实问答用低T，创意写作用高T；
  • top-k / top-p（核采样）：只在概率前k名/累积p内采样——截断长尾防胡说；
  • KV缓存：自回归生成时缓存已算过的K/V，避免重复计算——推理加速第一招。

1.4 关键概念速答

概念 一句话
幻觉 模型一本正经编造——来自"预测最像的词"而非"查证事实"；缓解：RAG、要求引用、校验器、低温度
In-context learning 不改权重，靠上下文里的示例就学会任务（few-shot）
CoT思维链 让模型"一步一步想"再答——推理类任务准确率大涨；衍生：自洽（多次采样投票）
涌现能力 规模跨过阈值后突现的新能力（争议存在，但复试可谈）
上下文 vs 权重 上下文=短期工作记忆（贵、即失）；权重=长期知识（训练写入）——这是理解Agent记忆设计的钥匙

二、RAG 检索增强生成（Agent的知识外挂）

2.1 为什么需要RAG（三大痛点直击）

①知识冻结（训练截止后的事不知道）；②私有数据不在训练集里；③幻觉——让模型基于检索到的原文回答并引用，可溯源。

2.2 标准RAG管线（能默画=入门）

离线索引：文档加载 → 切分chunking（按语义/固定token+重叠）→ Embedding模型向量化 → 存向量数据库（FAISS/Milvus/Chroma等）。 在线查询：问题向量化 → 相似度检索top-k（余弦相似度）→ （可选）重排rerank → 拼进提示词 → LLM生成带引用的回答。 【数学连接】embedding检索=第2批KNN：在高维语义空间找最近邻；余弦相似度=向量夹角（你线代的内积/夹角公式直接用上）。

2.3 工程要点（复试区分度所在）

  • chunk大小是第一超参：太小丢上下文、太大稀释相关性；重叠切分保连贯；
  • 混合检索：向量（语义）+BM25（关键词）取长补短；
  • 查询改写：把用户口语问题改写成适合检索的形式（Agent里常让LLM自己做）；
  • 评估：检索命中率（召回上下文了吗）+回答忠实度（是否忠于检索内容）——引用第2批评估指标思想。

2.4 RAG vs 微调（标准对比题）

RAG改"知道什么"（知识），微调改"怎么说话"（行为/风格/格式）；知识频繁更新→RAG；固定输出格式/领域语感→微调；两者常组合。优先试RAG（便宜、可溯源、即时更新）。

三、AI Agent 智能体（你的主方向）

3.1 定义与"感知-规划-行动"循环

Agent = LLM当大脑 + 工具当手脚 + 记忆当笔记本 + 规划当日程表，在环境里循环：感知（观察输入/工具结果）→ 思考（推理下一步）→ 行动（调工具）→ 观察（结果回填）→ 循环，直到判定任务完成。 与Chatbot的本质区别：Chatbot一轮回答；Agent多步闭环、能改变外部世界状态（发邮件/写文件/调API）。

3.2 ReAct范式（必会默画，Agent的第一块基石）

Reason + Act 交替：

Thought: 我需要先查天气
Action: weather_api(城市=重庆)
Observation: 晴，32℃
Thought: 用户问穿什么，结合温度给建议
Answer: 短袖即可……

【为什么有效】把"想"和"做"显式交错——行动结果反馈进思考，比一次性规划更容错；也是CoT（推理）+工具（行动）的自然结合。 衍生范式（说得出=加分）：Reflexion（失败后自我反思写入记忆再重试）、Plan-and-Execute（先全盘规划再逐步执行，省token）、多智能体（分工协作/互相审校）。

3.3 工具调用 Function Calling（Agent的手）

流程四步：①开发者用schema（JSON）描述工具（名称/功能/参数）；②LLM判断需要工具时输出结构化调用请求（工具名+参数）；③运行时（你的代码）真正执行；④把结果回填给LLM继续。 【关键认知】模型只"说"要调什么，不自己执行——执行权在应用侧（安全边界也在这）。让模型做它擅长的（理解、决策、填参数），让程序做它擅长的（确定性执行）。 工具生态标准化：MCP（Model Context Protocol）等协议把"工具/数据源接入"标准化成即插即用——2025年以来Agent生态的关键基建（复试可谈"工具生态正在协议化"）。

3.4 记忆系统（对照人脑三层）

层 实现 寿命
短期记忆 上下文窗口（对话历史） 会话内，窗口有限
长期记忆 向量库存储历史/笔记，检索召回 跨会话
工作记忆/草稿 让模型外写到文件/记事本（scratchpad） 任务内
【工程问题】上下文塞不下→摘要压缩；重要事实→写入长期记忆；这正是"上下文vs权重"钥匙的应用。

3.5 Agent的可靠性与评测（研究味道最浓的部分，适合谈"我想做什么"）

  • 失败模式：死循环、幻觉工具参数、过早宣布完成、级联错误；
  • 对策：步数上限、每步校验、自我检查（critic）、人审关键步（human-in-the-loop）；
  • 评测：端到端任务成功率（SOTA基准思想）+过程审计（工具调用轨迹对不对）——Agent评测本身就是热门研究方向（复试谈方向的金句："生成容易验证难，Agent的瓶颈正在从'能不能'转向'稳不稳'"）。
  • 成本：多步×每步token——缓存、小模型分流（路由）等工程手段。

四、微调与部署（够用即可）

  • LoRA（低秩适配）直觉：冻结原权重 ΔW≈BA（低秩分解），只训练极小参数量——"给大模型插可拔插的外挂"，消费级GPU可微调；QLoRA=量化+LoRA再省一档；
  • 量化：FP16→INT8/INT4，显存大降、精度微损（推理部署标配）；
  • 推理加速：KV缓存（1.3）、批处理、投机解码（小模型草稿大模型审）——概念级；
  • 开源生态：HuggingFace（模型/数据集/transformers库）是事实标准门户。

五、复试问答精选（LLM/Agent方向18题·考官问-标准答）

  1. 什么是幻觉，怎么缓解？ ——模型按"词的似然"而非事实生成；缓解：RAG提供依据、要求引用来源、低温度、生成后校验。
  2. Chatbot和Agent的区别？ ——单轮应答 vs 感知-规划-行动多步闭环并作用于环境。
  3. 画ReAct并解释。 ——Thought→Action→Observation循环（默画3.2图）。
  4. Function calling谁执行？ ——模型只输出结构化调用意图，应用侧执行后回填——安全与确定性边界。
  5. 温度调0会怎样？ ——近贪心解码，输出稳定但可能重复；适合代码/事实任务。
  6. RAG为什么比微调适合知识更新？ ——知识在数据库里改了即时生效、可溯源；微调要重训且容易过时。
  7. RAG检索不准怎么优化？ ——调chunk、混合检索、查询改写、重排、embedding模型换更强的。
  8. Agent的记忆怎么设计？ ——短期上下文+长期向量库+外写草稿；塞不下则摘要压缩。
  9. 为什么注意力要除√dₖ？ ——（接第3批）防点积方差过大→softmax饱和→梯度消失。
  10. LoRA为什么省？ ——低秩假设：ΔW≈BA，可训参数降几个数量级，原模型冻结。
  11. GPT三个训练阶段？ ——预训练（next token）→SFT（指令微调）→RLHF/DPO（对齐人类偏好）。
  12. CoT为什么有效？ ——把推理外化成显式中间步骤，等于给模型"草稿纸"，复合问题的错误不再一步到位地犯。
  13. Agent怎么防死循环？ ——步数上限+完成判据校验+反思机制+关键步人工确认。
  14. 多智能体适合什么场景？ ——可并行分解（分头检索）、需对抗校验（生成者+审校者）；代价：token翻倍、错误也可能级联。
  15. 上下文窗口和知识库的关系？ ——窗口是工作内存（贵而有限），知识库(RAG)是外存；工程=把对的上下文在对的时刻搬进窗口。
  16. 为什么Agent评测难？ ——任务成功≠过程正确；轨迹长、环境非确定、成本高；基准易被污染——开放研究问题。
  17. Transformer为什么取代RNN做LLM？ ——（接第3批题4）全并行训练+任意位置O(1)直连。
  18. 你为什么选Agent方向？（送分题，准备自己的版本）——参考框架："生成模型能力已强，瓶颈转到可靠落地：工具使用、记忆、多步规划与评测——Agent是LLM从'会说'到'会做'的关键一层，工程与研究空间都大。"（务必加上自己的经历：算法课项目/本库资料自动化建设的体会）
