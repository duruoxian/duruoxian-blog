408 · 计算机组成原理精讲 · 指令系统与CPU（寻址计算 + 流水线演算）

计组精讲第3批。指令系统抓扩展操作码设计与寻址方式EA表，CPU抓数据通路与流水线三类冒险——408大题"流水线时空图"的原理底座。

第4章 指令系统

一、指令格式精讲

I1 指令构成：操作码（做什么）+地址码（对谁做）。地址码个数：四/三/二/一/零地址。 I2 定长操作码 vs 变长（扩展）操作码： - 定长：规整硬件简单（RISC）； - 扩展操作码：短码不给长码当前缀（前缀一致性），指令空间指数级利用（CISC）。 【扩展操作码设计规则（必会）】①短操作码不能与长操作码前缀重合；②各类指令数用逐层分配验证：4位码留1个扩展口(1111)→下级可扩 16×16=256 种…

考题1（扩展操作码·408经典设计题） 指令字长16位，每个地址码字段4位。设计：三地址指令15条、二地址指令15条、一地址指令15条、零地址指令16条。写出操作码分配方案。 【解】 | 类型 | 操作码（16位） | 数量 | |---|---|---| | 三地址 | 0000~1110（4位） | 15 | | 二地址 | 1111 0000~1111 1110（前4位1111+4位） | 15 | | 一地址 | 1111 1111 0000~1111 1111 1110（前8位1111 1111） | 15 | | 零地址 | 1111 1111 1111 0000~1111 1111 1111 1111 | 16 | 验证前缀不冲突：短码(如1111)不是任何长码的"完整前缀位置"冲突——每个层次留口1111向下扩展。∎ （另一常见问法：给出某条指令的操作码，判断它是几地址指令——看前缀落入哪一层。）

二、寻址方式精讲（EA表+访存次数）

A1 指令寻址：顺序（PC+1"1"=指令长度）、跳跃（转移指令）。 A2 数据寻址十种（EA=有效地址）： | 寻址 | 有效地址 | 取操作数访存 | 特点/用途 | |---|---|---|---| | 立即 | 操作数在指令中 | 0次 | 最快；只作源 | | 直接 | EA=A | 1 | 简单；寻址范围受A位限制 | | 一次间接 | EA=(A) | 2 | 扩大范围；慢 | | 寄存器 | EA=Rᵢ（操作数在寄存器） | 0 | 快、指令短 | | 寄存器间接 | EA=(Rᵢ) | 1 | 扩大范围 | | 相对 | EA=(PC)+A | 1 | 便于程序浮动（代码移植） | | 基址 | EA=(BR)+A | 1 | 面向操作系统：程序重定位（BR由OS装、执行中不变、A可变） | | 变址 | EA=(IX)+A | 1 | 面向用户：数组循环（IX可变、A不变） | | 堆栈 | EA=(SP) | 1 | 硬堆栈在CPU/软堆栈在内存 |

考题2（相对寻址·转移目标计算） 转移指令地址4000H，指令长4B，相对偏移量−100（十进制）。求转移目标地址。 【解】取指后PC=4000H+4=4004H；目标=PC+偏移=4004H−64H=3FA0H。∎ （关键：相对寻址以"取出指令后的PC"为基准——PC已自动加过指令长度。）

考题3（访存次数计算） 一条一地址取数指令（LOAD），操作数采用一次间接寻址。指令执行全程共访存几次？ 【解】取指令1次 + 间址阶段取有效地址1次 + 取操作数1次 = 3次。∎ （若为寄存器寻址：只1次（取指）。寻址方式×指令类型→访存次数，408选择题钉子。）

考题4（基址vs变址·辨析） 处理数组 a[i] 的循环程序与程序在内存中的重定位，各适合哪种寻址？为什么？ 【答】数组→变址（IX内容可变、形式地址A=数组首址不变，面向用户）；重定位→基址（基址寄存器由OS装入、执行中不变、形式地址可变，面向系统）。∎ （口诀：基址管搬家、变址管循环。）

A3 CISC vs RISC（对比表·必背）： | | CISC | RISC | |---|---|---| | 指令 | 数量多、变长 | 少、定长 | | 寻址 | 丰富 | 少 | | 访存指令 | 多数指令可访存 | 只有Load/Store访存 | | 控制器 | 微程序 | 组合逻辑（硬布线） | | 寄存器 | 少 | 大量通用寄存器 | | 流水线 | 难优化 | 适合流水线 | | 目标代码 | 省空间 | 用空间换时间 |

第5章 中央处理器

一、CPU结构与寄存器

C1 CPU四大功能：指令控制、操作控制、时间控制、数据加工。 C2 寄存器两类： - 用户可见：通用寄存器、条件码； - 用户不可见（控制与状态）：MAR、MDR、PC、IR、微指令寄存器。 【要点】PC存放下一条指令地址、有自动加1功能；IR存当前指令；MAR/MDR位数=地址线宽/存储字长。

二、数据通路与指令执行

D1 数据通路：数据在功能部件间传送的路径（含控制信号）。单总线（简单慢、冲突多）vs 多总线/专用通路（快，配合流水线）。 D2 指令周期四阶段数据流： - 取指：PC→MAR→M→MDR→IR，PC+1（所有指令相同）； - 间址：（IR地址码）→MAR→M→MDR→IR地址码； - 执行：按操作码分派（算逻→ALU；访存→MAR/MDR；转移→改PC）； - 中断：响应条件（指令周期结束）→关中断→保存断点→服务程序。 D3 控制器两种实现： - 硬布线：组合逻辑直接产生控制信号——快、RISC用、改指令难； - 微程序：控制信号编码存于控制存储器CM（ROM）——一条机器指令=一段微程序，一条微指令=一组微命令；水平型微指令（并行能力强、字长长）vs 垂直型（像机器指令、需译码）； 【对比】微程序：规整易扩展、速度慢（访CM取微指令）；硬布线：快、难修改。CM在CPU内部、对程序员透明（不可见）。

三、指令流水线（计算主战场）

P1 五段流水线：IF取指 → ID译码/取数 → EX执行 → MEM访存 → WB写回，每段一个时钟周期。 三大性能指标： - 总时间 = (k+n−1)×Δt（k段、n条指令）； - 吞吐率 Tp = n/[(k+n−1)Δt] → 极限 1/Δt； - 加速比 S = 串行时间/流水时间 = nkΔt/[(k+n−1)Δt] = nk/(k+n−1) → 极限 k。 P2 三类冒险与处理（必背）： | 冒险 | 场景 | 处理 | |---|---|---| | 结构 | 部件资源冲突（如访存指令与取指争存储器） | 停顿；指令存储器与数据存储器分开（哈佛结构）；资源重复 | | 数据 | 后条要用前条结果（RAW读后写最常见） | 转发/旁路；停顿（插入气泡）；编译调度 | | 控制 | 转移指令改变PC | 分支预测、延迟槽、尽早生成转移地址 | 【load-use要点】load后的指令要用load的结果：即使有转发也需停1拍（数据MEM段末才可用，下条EX需在其后）。 P3 影响因素与高级技术：超标量（多发射，空间并行）、超流水（更细分段，时间并行）、超长指令字VLIW（编译器打包）。

四、本章考题（5题）

考题5（五段流水线·基础计算） 五段各100ns，连续执行12条指令（无冒险）。求总时间、吞吐率、加速比。 【解】T=(5+12−1)×100=1600ns；吞吐率=12/1600ns=7.5×10⁶ 条/s；串行=12×500=6000ns → 加速比=6000/1600=3.75。∎

考题6（load-use冒险·时空图） 五段流水线（同上），第2条指令是load，第3条指令立即用其结果（无转发）。求执行4条指令的总时间与气泡数。 【解】第3条的EX需要load的数据（MEM段末才可用）→ 第3条在ID后停顿直至load的MEM完成： | 拍 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | |---|---|---|---|---|---|---|---|---|---| | 1 | IF | ID | EX | ME | WB | | | | | | 2 | | IF | ID | — | — | EX | ME | WB | | | 3 | | | IF | — | ID | — | EX | ME | WB | | 4 | | | | IF | — | ID | — | EX | WB? ME | ——第3条MEM在8、WB在9；第4条EX在8、WB在10？逐拍排（EX后MEM、WB）： 最终：总时间=10拍=1000ns，插入2个气泡（无转发时load-use停2拍）。∎ （若有转发（MEM末→EX首），第3条EX紧随load的MEM，仅停1拍——"转发省1拍"是结论。）

考题7（分支预测·控制冒险） 无分支预测时每次转移指令造成几拍损失？动态分支预测的意义？ 【答】转移指令在EX末才知道方向 → 后续已取指令作废，流水线冒空（5段损失约2~3拍）。动态分支预测（BHT记录历史）猜中则零损失——现代CPU预测准确率>90%，这就是"预测失败代价大但平均收益大"的权衡。∎

考题8（微程序概念链） 按从大到小排序"机器指令/微程序/微指令/微命令"，并说明相邻层的关系。 【答】机器指令 → 微程序 → 微指令 → 微命令。一条机器指令对应一段微程序，一段微程序由若干微指令组成，一条微指令包含若干微命令（微命令=微操作的控制信号）。CM（控制存储器）用ROM实现、在CPU内。∎
