## 2. 写文章

### 2.1 方式一：后台可视化（推荐）

打开 `/admin` → **新建文章** →（可选）**导入 .md** 选本地文件 → 填标题/分类/标签 → 写正文 → **保存草稿**或**保存并发布**。

- 编辑器支持 **Ctrl+S**（Mac Cmd+S）快捷保存；有未保存内容时返回/关页面会先确认
- **导入 .md** 的智能处理：文件带 front-matter 时自动填标题/日期/摘要/分类/标签；没有时自动取首个一级标题当标题、用文件名生成网址建议；编辑已有文章时仅替换正文
- 图片：正文里「插入图片」、封面上传，文件自动存入 `public/images/posts/`
- 保存 = 提交 GitHub → 自动部署，约 2 分钟后线上生效

### 2.2 方式二：本地写 Markdown

在 `content/posts/` 新建 `.md` 文件（文件名 = 网址，用小写英文/拼音）：

```markdown
---
title: "文章标题"
date: 2026-10-05
description: "一句话摘要，显示在列表和搜索里"
category: "技术"              # 技术 / 生活 / 项目（现有：技术、生活、项目、工具）
tags: ["标签一", "标签二"]    # 随便加新标签，保存后自动生成标签页
series: "系列名"              # 可选
cover: "/images/posts/xxx.jpg" # 可选，图片放 public/images/posts/
draft: false                  # true = 草稿，不显示在网站上
---

正文用 Markdown 写。
```

### 2.3 发布链路

`git push` → GitHub Actions 自动 `npm ci` → `npm run build` → 部署到 Cloudflare Pages（约 2 分钟）。
工作流定义在 `.github/workflows/deploy.yml`，需要的密钥 `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` 已配置好。

## 3. 图形化后台 /admin

### 3.1 它是什么

和博客长得一模一样的管理界面（同款顶栏/极光/深浅色主题）：文章列表（封面缩略图、篇数统计、草稿标记）、
文档式编辑器（大标题、分类药丸、封面实时预览、带工具栏的 Markdown 编辑区、预览模式）、站点信息表单（站点/作者两组）。

### 3.2 登录与安全原理

- 后台页面本身只是个「壳」，公开发布、不含任何秘密；**所有数据在你的 GitHub 仓库里**
- 登录 = 输入你的 **GitHub 令牌（PAT）**，存在**你自己浏览器**的 localStorage；之后免登录
- 每次读写都拿令牌去问 GitHub：钥匙对 → 给数据；钥匙错/没有 → GitHub 直接拒绝（401）
- 令牌是细粒度的，只授权了这一个仓库；别人打开 /admin 只会看到登录框
- robots.txt 已屏蔽 /admin（搜索引擎不收录）
- **两个弱点**：别让陌生人用你开着的电脑；令牌泄露（贴网上/发给别人）就去 GitHub 重新生成

### 3.3 速度原理

文章列表存在浏览器本地缓存里，打开后台**先用缓存秒开**，再后台按每篇文章的 sha 增量同步
（仓库没变化时整次同步只有 1 个请求）；加载中有骨架屏，视图切换带过渡动画。

## 6. 部署架构

- `next.config.ts` 配置了 `output: "export"`：构建生成纯静态 `out/`，托管在 Cloudflare Pages（免费、自动 HTTPS）
- 日常**只需 git push**；手动备用命令 `npm run deploy`（= 构建 + wrangler 直传，需本机 wrangler 登录过）
- 绑定自己的域名（可选，未做）：买 `.cn` 域名并实名 → Cloudflare 控制台 Pages 项目 → Custom domains →
  按提示加 CNAME → 改 `src/lib/site.ts` 的 `url` → push。海外托管不需要 ICP 备案
- 备选托管（了解即可）：Vercel（国内常慢）、GitHub Pages（国内较慢）、国内 OSS+CDN（需备案）

## 8. 原理速览（想深入再看）

- **App Router**：目录即路由；`[slug]` 动态路由；`layout.tsx` 全站布局；`generateStaticParams` 构建期生成全部文章页（SSG）；
  `generateMetadata` 生成 SEO 元信息。注意 Next 16 里 `params` 是 Promise，必须 `await`
- **内容管线**：`gray-matter` 拆 front-matter → `unified` 管线（remark-parse/gfm/rehype → slug → autolink → highlight → stringify）
  渲染 HTML；标题锚点用 github-slugger，目录跳转两侧算法必须一致
- **静态导出**：`output: "export"` 后无 Node 服务器，`rss.xml`/`sitemap` 等需显式 `force-static`；本站无服务端功能，无影响
- **深色模式防闪屏**：`layout.tsx` 里内联主题脚本抢在渲染前读 localStorage 给 `<html>` 加 `.dark`（避免 FOUC）；
  主题三态（跟随系统/亮/暗）由 `data-theme` + CSS 变量控制
- **视觉体系**：极光背景（globals.css 渐变光斑动画）、玻璃卡片（`gradient-border`/`backdrop-blur`）、
  渐变文字（`gradient-text`）、卡片光晕（`card-glow`）——后台复用同一套类
- **后台数据流**：浏览器直接用你的 GitHub 令牌调 Contents API（列目录 → 按 sha 增量拉文件 → PUT 提交），
  每次提交触发 Actions 部署；列表缓存于 localStorage（键 `admin:cache:posts`）

## 9. 常见问题排查

| 现象 | 原因 / 解决 |
| --- | --- |
| 后台打开还是旧样子 | 浏览器缓存，**Ctrl+F5 强刷** |
| 文章不显示 | 检查文件在 `content/posts/`、front-matter 的 `---` 成对、`draft` 是否为 true |
| 文章图片不显示 | 图片须在 `public/images/posts/`，引用路径 `/images/posts/...` |
| git push 失败 | github.com 时通时断：直连失败就开 Clash 并加 `-c http.proxy=http://127.0.0.1:7897` |
| 后台保存报 409 | 文章刚被别处更新过，返回列表刷新后再保存 |
| 后台提示登录过期 | 令牌失效/被删，重新生成并在后台粘贴一次 |
| 线上还是旧内容 | 等 2 分钟部署完成 + Ctrl+F5 强刷 |
| 构建报类型错误 | `npm run build` 看行号，多半是 `params` 忘了 `await` |
| GitHub API 中文请求 400 | GBK 控制台问题，改用 Python urllib（UTF-8） |

## 10. 安全备忘

- 后台页面公开无秘密，**权限全部在令牌里**；GitHub 只认证不认人（错误令牌一律 401）
- 令牌存在各设备浏览器的 localStorage；只在个人设备上登录后台
- 令牌在聊天/网页中暴露过就重新生成（GitHub → Settings → Developer settings → Tokens），换完各设备重粘一次
- 访问统计、评论系统等尚未开启（见下）；开启方式需要时再补
