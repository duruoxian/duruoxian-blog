## 先说结论：现在它是什么

v0.1.52 的 webai2api：

| 能力 | 状态 |
|---|---|
| 四平台 10 个模型 | DeepSeek 2 / 智谱 2 / Kimi 3 / 千问 3，思考档位全部支持 |
| 工具调用 | 四平台全部可用；`qwen3.8-max` 如实标注「实验性」 |
| Anthropic 兼容 | `POST /v1/messages`，流式 + 工具调用，Claude Code / ZCode 原生接入 |
| 图片输入 | DeepSeek、GLM 支持消息带图，自动上传到对应平台 |
| 版本形态 | 单一开源版本，MIT，完全免费 |
| 质量基线 | 测试 309 → 662 全绿；面板四层测试网 + Playwright 真浏览器 E2E |

关于「实验性」要多说一句：第三篇里修好的是多路候选回答**串行咬字**的
解析问题——那是适配层的 bug，能修。但 `qwen3.8-max` 模型本身在网页反代
下的稳定性问题（偶发语序混乱、逻辑跳跃）是模型侧的，适配层修不了。
代码注释里写明「生产用途建议 qwen3.7-plus」，面板照实标注。能修的修，
修不了的标注，这个系列一直在做的事到最后一篇也没变。

## 一、v0.1.36：把双版本合成一个

完结篇的第一个动作不是加功能，是删复杂度。

当时这棵代码树上养着两个形态：Pro（8800 端口，全功能）和 lite
分支（8802，精简面板），外加一层贯穿全库的门禁状态。代价是
全局性的：每个功能做两遍、每层代码都要绕开门禁、两个面板各改
各的——双版本把每一行代码都变贵了。

10 月 27 日，v0.1.36 发布：**合并为单一版本，门禁机器整目录删除**
（`license` / `issuer` / `ed25519` 及相关面板、测试）；随后 lite
分支物理删除、全库死代码清扫，净删 400+ 行。从此只有一个 exe、
一个面板、一个版本号，MIT 完全开源免费。

有一笔账要算清楚。**性质的账**：这个工具的本质是复用网页版
会话，第一篇就把丑话说在前面——可能违反平台服务条款，有封号
风险。免费开源加「仅供个人学习与本地自用」的声明，才是和这件
事的风险相称的姿态。**成本的账**：门禁与双分支是没有尽头的
复杂度税，每一次改动都在为两个形态买单。**时间的账**：408 的
15 个月备考规划在十月已经铺开，而这个项目最有意思的部分（协议
逆向、流式工程、工具链模拟）已经做完了，剩下的是重复劳动。

删的时候没有留任何迁就：门禁代码不留开关、不留注释尸体，直接
删干净。事后看清的一个观察：这次「做减法」不是项目衰落的开始，
恰恰相反——此后一周是整个项目最密集的工程期。v0.1.39 到
v0.1.52 的全部内容（Anthropic 端点、图片输入、五波审计、面板
改造）都发生在单一版本化之后。卸掉包袱，剩下的时间全部花在了
「好用」上。

## 二、Anthropic 兼容端点：Claude Code 和 ZCode 原生接入

v0.1.33 上线了 `POST /v1/messages`——不是又一个「兼容层」，而是
让 Claude Code、ZCode 这类 Anthropic 母语的客户端**不经任何转换**
直连网页模型：base_url 指过来，工具调用、流式、多轮全套可用，
面板一键接入区也生成了对应的接入片段。

协议适配的坑比预想的多，最典型的是**并行工具调用的第二条整体丢失**
——参数还拼进第一条，变成非法 JSON。Claude Code 单轮并行
Read + Bash 是高频动作，一触即中。根因在流式换号的 `_switch` 里：
它只感知 message→tool 的块切换，感知不到 tool→tool 换 id，于是
第二个 tool_use 被当成第一条的延续。修法是按调用 id 切新
content_block。

同族的两个：tool_use 参数被思考文本打断后重开的块变成无名块
（记住 id 和 name，重开时合并更新）；tool_result 乱序到达时按
id 精确配对。另有纯图片消息被整条蒸发的问题，降级为 `[图片]`
占位——Anthropic 层现在跑着 ZCode / Claude Code 的日常主路径，
这一层是五波审计里修得最狠的地方。

## 三、图片输入：GLM 的 chat_upload 逆向

编码代理开始频繁带图之后，一个尴尬暴露了：DeepSeek 的图片链路
早就通了，智谱一直缺。用户侧的体感是，同一个 agent 在
DeepSeek 上能看截图，换 GLM 就自称「我是纯文本模型」。

真机抓包发现网页端有两套上传接口。顺着 `backend-api` 那条传，
永远回「权限不足」——那是智能体的**文档**上传，不是聊天图片。
真正的入口是 `productivity-api/file/chat_upload`，消息里
image part 的字段（`file_id` / `image_url` / `file_size` /
`order`）逐字对齐网页端之后，GLM 的图通了。

工程上的收尾：

- 消息含 `image_url` 自动上传，LRU 缓存去重，同一张图不重复传；
- 单张失败降级纯文本，不因一张图毁掉整轮对话；
- 复用轮只看最后一条 user 消息取图，纯文本轮不再误挂历史旧图。

以及诚实条款：Kimi、千问暂不支持图片，面板接入片段此前把它们
谎报成支持——这次一并收回，与后端能力对齐。

## 四、让模型相信自己有手：「身份与环境」锚定块

工具链稳定运行之后，剩下最后一种失败：模型自己不配合。

症状是偶发的——让编码代理干活，模型突然回复「我是一个网页助手，
无法访问你的文件系统」；或者更隐蔽的，一本正经地叙述
`sandbox://`、`/mnt/agents` 这样的云沙盒世界观，把文件「写」到
一个不存在的地方，然后宣布任务完成。

根因想通了很简单：**模型对自己的认知来自训练数据**——它的名字、
它的官方网页、它的云端产品形态。工具协议提示词只告诉它
「你有哪些工具」，从没告诉它「你现在在哪」。

修复是四家工具协议头部统一注入一段【身份与环境】锚定块：你运行
在用户的 Windows 编码代理内、不在云端也不在隔离沙盒、消息里的
路径就是本地路径、禁止沙盒叙事、禁止自称网页助手、文件必须写到
用户指定的本地路径。五家各自对齐之后，「没手」叙事基本绝迹。

配套的两个补丁：

- **DeepSeek「光说不做」自愈**：思考里已经有完整的调用草稿、正文
  却空着且没有正式调用时，同会话追加一条 user 提醒再给一轮。
  四个条件同时满足才触发、每请求最多一次；「思考草稿绝不直接执行」
  的安全线原样保留——自愈不等于放松标准。
- **工具名模糊匹配**：模型写 `Bash`、声明里是 `bash`（或 `-`/`_`
  漂移）不再静默丢弃，且按声明的名字下发。这个此前只有 DeepSeek
  有，这次四家拉平。

## 五、五波深读审计：从「看起来能用」到「敢依赖」

单一版本化之后，把省下来的时间换了个花法：四波外部深读审计加一轮
自审复审，全部确定性发现修复；配套的测试从 309 涨到 662，面板
前端补了四层测试网（契约 / 主题矩阵 / 健康防线 / 真浏览器走查），
Playwright 真浏览器 E2E 18 项。

挑几个值得记的：

**粘性键的 1→2 轮断档。** 首轮请求没有 assistant 历史，会话缓存存
的是「无 assistant 键」；第 2 轮客户端把回复回传，键变了，精确
查询必然 miss。单账号时侥幸命中把它掩盖了；多账号池严格轮询下，
GLM 两个健康号**每一轮都在新建上游会话**，长对话被全量压平——
防风控设计被自己的调度精确击穿。修法是精确 miss 时回退查
`ignore_assistant` 变体键，第 2 轮成功后按回传键重设。这类 bug
的可怕之处在于：每一层单独看都对，组合起来才错，而且换个部署
形态症状就消失。

**日志系统把自己锁死。** windowed exe 的 stdout 兜底在
`handler.flush` 里拿一把不可重入的锁，而 `emit` 途中的 `print`
又请求同一把锁——死锁的结果是 exe 卡死在初始化之后，**一行日志
都不出**。全程序最不该出问题的地方出了问题，而且症状恰恰是
「没有任何输出」。日志是排障的底线，底线自己不能是嫌疑人。

**防风控停顿占着槽位睡觉。** DeepSeek 请求前 20–60 秒的随机停顿
放在了并发槽位获取**之后**——高峰期它一边睡觉一边占着宝贵的
槽位，其他请求全部排队。移到 acquire 之前，一行顺序，
差一个吞吐量级。

**空响应的口径。** 正文以 200+ 空白结尾的流被滑窗误判为全空，
触发重试 → 「两份回答拼接」「思考被顶成正文重复下发」这些第三篇
遗留的灵异现象，最后都归到这一个口径上。空判定改用全量已发正文，
四家统一。断流（RST / 超时）也不再让已输出的流变报错，自动续写
救回，零输出的流弃会话重试。

收官验收：四平台 + Anthropic 端点真机冒烟全部通过，含工具调用与
多轮回填真实写文件。

## 六、面板：门面与仪表

最后一周的另一半时间给了面板：

- **主题系统**：四套预设（极简白 / 极简黑 / 液态浅色 / 液态深色）
  + 自定义底色——选自定义不预设任何颜色，按钮色按底色自动推导
  同色系；
- **数据支撑**：账号页每行显示「最近失败：错误码 + N 分钟前」，
  哪个号在报什么错一眼可见；模型用量表加失败列；Key 表加今日
  token；总览加均耗 / 首字；接入页显示 opencode 已接入 / 未接入
  标签；CSV 导出跟随界面筛选；
- **十六项 UI 修复**：Esc 关免责弹窗把面板软锁、14 处「失败也
  提示已保存」、菜单孤儿浮层、防连点卡死……全是真浏览器走查
  一个个抓出来的；
- **门面**：README 去表情符号重排、截图用 Playwright 登录后逐页
  重制（截图时账号数据临时净化、真实数据即时恢复）、补齐
  README_EN 英文版。

## 七、为什么到这里完结

一个工具什么时候值得写完结篇？我的判断是三个事实同时成立的时候：

1. **该有的都有了。** 四平台、工具调用、图片输入、双协议端点、
   多账号调度、面板、统计——清单上没有悬空项；
2. **它已经是基础设施。** 它不再是我「维护的项目」，是我每天
   真实依赖、真实在用的东西；
3. **剩下的问题都是打磨级别的。** 不再需要攻防、不再需要逆向、
   不再需要架构决策——这三种故事都讲完了，剩下的修订不值得
   占用一篇的篇幅。

完结不等于弃坑。仓库还在，issue 会看，bug 会修，平台改版会跟着
适配。只是它不再是一个「项目故事」，回归成一个「工具」——工具
成熟的标志，就是从值得写文章，变成不值得写文章。

至于我自己：408 的 15 个月备考规划十月铺开，接下来教室的时间会
比终端多。这四篇里沉淀的方法论——抓数据不猜协议、用真实客户端
验收、诚实面对没测过的东西——换一个考场照样用得上。

最后把四篇连起来看：

| 篇 | 版本 | 一句话 |
|---|---|---|
| [第一篇](/posts/webai2api) | v0.1.7 | 把网页版变成软件：账号池、Key 分发、按 Key 计量 |
| [第二篇](/posts/webai2api-v2) | v0.1.20 | 四平台全打通——Connect 协议、隐藏中继，与封号的两个根因 |
| [第三篇](/posts/webai2api-v3) | v0.1.32 | 给没有 tools 协议的网页模型模拟出完整的工具调用链 |
| 完结篇（本篇） | v0.1.52 | 单一版本化、审计收官——从项目故事回归工具本身 |

第一篇的结论是「把它当软件做」；第二篇是「细节全是反直觉的」；
第三篇是「真实使用者是最高优先级的测试用例生成器」；这一篇的
结论最简单：**把花哨的部分删干净，把剩下的每一天都花在「配得上
日常」上。**
